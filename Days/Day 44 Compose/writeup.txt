# Running Apache with Docker Compose: A Step-by-Step Write-Up

*How I deployed an `httpd` container with Docker Compose, the mistakes I made along the way, and how each one was found and fixed.*

---

## 1. The goal

The task was to run an Apache web server in a Docker container on **App Server 1** in **Stratos DC**, using Docker Compose. The requirements:

1. The Compose file must be at exactly **`/opt/docker/docker-compose.yml`**.
2. The container must use the **`httpd:latest`** image.
3. The **container** itself must be named **`httpd`**. The service name inside the file can be anything.
4. Port **80** inside the container must be reachable on port **6200** of the host.
5. The host directory **`/opt/sysops`** should be served as the website content (Apache's document root, `/usr/local/apache2/htdocs`).

If you just want the answer, jump to [Section 4](#4-the-final-working-file). If you want to understand *why* it looks the way it does, and avoid the same traps, read on.

---

## 2. A few concepts first

You don't need deep Docker knowledge to follow this, but four ideas come up repeatedly.

**Docker Compose** lets you describe a container in a YAML file instead of typing a long `docker run` command. You then start everything with `docker compose up -d`.

**YAML is indentation-sensitive.** Structure is expressed purely by how far each line is indented, a bit like Python. Two rules matter most:
- Indentation must use **spaces only**. Tab characters are forbidden.
- Items that belong to something must be indented **further** than it, and items at the same level must line up exactly.

**Port mapping** is written `"HOST:CONTAINER"`. `"6200:80"` means "traffic arriving at the host on port 6200 is forwarded to port 80 inside the container". The right-hand number must be the port the application actually listens on. For Apache that's 80.

**Mounts** connect storage to a path inside the container. The two you'll meet here:
- A **bind mount** links a real directory on the host (e.g. `/opt/sysops`) into the container.
- A **named volume** is storage managed by Docker itself, kept under `/var/lib/docker/volumes/`.

## 3. The journey: four attempts

### Attempt 1: the file wouldn't even load

My first draft looked like this. I've written the tab characters as `<TAB>` so you can see them; in the editor they simply looked like wide indentation.

```yaml
services:
<TAB>httpd:
<TAB><TAB>image: httpd:latest
<TAB>ports:
<TAB><TAB>- "80:3000"
<TAB>volumes:
<TAB><TAB>- type: volume
<TAB><TAB>  source: httpd-data
<TAB><TAB>  target: /usr/local/apache2/htdocs

volumes:
<TAB>httpd-data
```

Running Compose produced:

```
yaml: line 2: found character that cannot start any token
```

**What this means:** the YAML parser hit a character it doesn't allow, here a tab, on line 2. Since tabs are invisible in most editors, you have to make them visible:

```bash
cat -A compose.yaml          # tabs appear as ^I, line endings as $
grep -nP '\t' compose.yaml   # lists every line containing a tab
```

On closer inspection, the tabs were only the first of four problems in this file:

1. **Tabs instead of spaces.** This is what stopped parsing at line 2.
2. **Wrong nesting.** `ports:` and `volumes:` were indented to the same level as `httpd:`, not deeper. YAML therefore read them as two *extra services* called `ports` and `volumes`, not as settings of `httpd`. Once the tabs were gone, this would have surfaced as `services.ports must be a mapping`.
3. **A missing colon.** At the bottom, `httpd-data` had no trailing colon, so YAML saw it as a plain word, not a named entry. Compose would complain `volumes must be a mapping`.
4. **The port was backwards.** `"80:3000"` forwards host port 80 to container port 3000, but Apache listens on 80, and nothing listens on 3000. This one wouldn't produce any error; the container would start and simply never answer.

> **Lesson:** YAML errors arrive one at a time. Fixing the first one often just reveals the next. Run `docker compose config` after every change; it parses the file and prints how Compose understood it.

---

### Attempt 2: valid, but not what the task asked for

I replaced the tabs with spaces, nested the settings correctly, added the colon and flipped the port:

```yaml
services:
 httpd:
  image: httpd:latest
  ports:
   - "3000:80"
  volumes:
   - type: volume
     source: httpd-data
     target: /usr/local/apache2/htdocs
volumes:
 httpd-data:
```

| What changed | Why |
|--------------|-----|
| Tabs → spaces | YAML only allows spaces |
| `ports` and `volumes` moved under `httpd` | Settings must be indented inside the service they belong to |
| `httpd-data` → `httpd-data:` | A named volume must be declared as a key |
| `"80:3000"` → `"3000:80"` | The container side must be Apache's port, 80 |

This file worked: Apache answered on `http://localhost:3000`. But it was built for a different spec, the wrong host port and no container name. It was a step forward in understanding, not the finished answer.

---

### A detour: an error that wasn't about the file

While testing, one command failed with:

```
unknown shorthand flag: '0' in -0
```

This message comes from the Docker command-line tool, not from Compose or YAML. It means a `docker` command received the option `-0`, which doesn't exist. The usual causes:

- a typo: the digit `0` typed instead of a letter such as `o` or `d` (they look alike in many fonts);
- a broken copy-paste that split a command across lines;
- the Compose plugin not being installed, so `docker` tries to read the flags itself. Check with `docker compose version`.

The fix was simply to retype the command carefully (`docker compose up -d`). `history | tail` shows exactly what was run.

---

### Attempt 3: the right ingredients, combined wrongly

Now targeting the real task, I wrote:

```yaml
services:
 httpd:
  image: httpd:latest
  volumes:
    - type: volume
      source: httpd-data
      target: /usr/local/apache2/htdocs
    - type: bind
      source: /opt/sysops
      target: /usr/local/apache2/htdocs
  ports:
    - "6200:80"
volumes:
  httpd-data:
```

The port was now right, but two problems remained.

**Problem 1: the container would have the wrong name.** The key `httpd:` under `services:` names the *service*, not the *container*. Without an explicit name, Compose generates one from the project (by default, the folder name) plus the service name plus a number. In `/opt/docker` that gives **`docker-httpd-1`**, which fails the "container must be named `httpd`" requirement.

**Problem 2: two mounts on the same path.** Both the named volume and the bind mount pointed at `/usr/local/apache2/htdocs`. A path inside a container can only have one thing mounted on it, so Docker refuses to start with `duplicate mount point`. Since the task names a host directory (`/opt/sysops`), the bind mount is the one to keep.

---

### Attempt 4: success

```yaml
services:
 httpd:
  image: httpd:latest
  container_name: httpd
  volumes:
    - type: bind
      source: /opt/sysops
      target: /usr/local/apache2/htdocs
  ports:
    - "6200:80"
```

| What changed | Why |
|--------------|-----|
| Added `container_name: httpd` | Sets the actual container name. It sits at the same level as `image:`, as a property of the service. |
| Removed the named volume | Only one mount is allowed per container path, and the task wants the host directory |
| Removed the top-level `volumes:` block | That block is only needed for named volumes; bind mounts don't use it |

Every requirement is now met.

---

## 4. The final working file

Here is the same configuration with tidy, uniform 2-space indentation, which is the recommended style:

```yaml
services:
  httpd:
    image: httpd:latest
    container_name: httpd
    ports:
      - "6200:80"
    volumes:
      - type: bind
        source: /opt/sysops
        target: /usr/local/apache2/htdocs
```

Save it as **`/opt/docker/docker-compose.yml`**. The name matters: if a file called `compose.yaml` sits in the same folder, Compose will prefer *that* one and may silently run the wrong configuration.

## 5. How to deploy it yourself

**Step 1: check the prerequisites.**

```bash
docker compose version                 # Compose is installed (some hosts use: docker-compose version)
ls -ld /opt/sysops                     # the directory to be served exists
ls -l /opt/docker/                     # only docker-compose.yml is in the folder
docker ps -a --filter name=^httpd$     # no old container is already using the name "httpd"
```

If an old `httpd` container shows up, remove it with `docker rm -f httpd`, or the new one will fail with a name conflict.

**Step 2: validate the file.**

```bash
cd /opt/docker
docker compose config
```

If this prints your configuration back without errors, the YAML is good.

**Step 3: start the container.**

```bash
docker compose up -d
```

`-d` runs it in the background.

**Step 4: confirm every requirement.**

```bash
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Ports}}'
# Expected: httpd    httpd:latest    0.0.0.0:6200->80/tcp

docker inspect httpd --format '{{range .Mounts}}{{.Type}} {{.Source}} -> {{.Destination}}{{end}}'
# Expected: bind /opt/sysops -> /usr/local/apache2/htdocs

curl -I http://localhost:6200
# Expected: HTTP/1.1 200 OK
```

**If `curl` returns 403 Forbidden**, there are two common reasons:
- `/opt/sysops` is empty. A bind mount shows exactly what's in the host folder, so add an `index.html`.
- SELinux (enabled by default on CentOS/RHEL) is blocking access. Check with `getenforce` and `ls -Z /opt/sysops`; see the `:z` option in the next section.

## 6. Ways to mount storage in Compose

There's more than one way to give a container storage. Here's each option, when to use it, and how to write it.

### Bind mount: "use this folder from my host"

Use it when you want the container to see files that already exist on the host, such as website content or config files. This is what the task needed.

Short form:

```yaml
volumes:
  - /opt/sysops:/usr/local/apache2/htdocs
```

Long form:

```yaml
volumes:
  - type: bind
    source: /opt/sysops
    target: /usr/local/apache2/htdocs
```

Both do the same thing, with one difference: if `/opt/sysops` doesn't exist, the **short form creates it** (empty, owned by root), while the **long form fails** with `bind source path does not exist`. In the long form, add `bind: { create_host_path: true }` if you want auto-creation.

Whatever is in the host folder *replaces* what the image had at that path. An empty host folder means an empty website.

### Named volume: "Docker, keep this data for me"

Use it for data the app produces and needs to keep across restarts, such as databases or uploads, when you don't care where on disk it lives.

```yaml
services:
  httpd:
    volumes:
      - httpd-data:/usr/local/apache2/htdocs   # short form
volumes:
  httpd-data:                                  # required declaration
```

Or the long form under the service:

```yaml
    volumes:
      - type: volume
        source: httpd-data
        target: /usr/local/apache2/htdocs
```

A handy property: the first time an empty named volume is mounted, Docker **copies in what the image already had** at that path. That's why you'd see Apache's default "It works!" page. After that, the volume's contents persist and take priority.

### Anonymous volume: "keep this, but I won't refer to it by name"

```yaml
volumes:
  - /usr/local/apache2/htdocs
```

Docker creates a volume with a random ID. It's hard to find or reuse later, so it's mostly for throwaway data.

### tmpfs: "keep this in memory only"

```yaml
volumes:
  - type: tmpfs
    target: /tmp
```

The data lives in RAM and disappears when the container stops. It's useful for scratch space or sensitive temporary files.

### Side-by-side

| Method | Where data lives | Needs top-level `volumes:` | Starts with image's files | Good for |
|--------|------------------|----------------------------|---------------------------|----------|
| Bind mount | A host folder you choose | No | No | Serving or editing host files, configs |
| Named volume | Docker's storage area | Yes | Yes (first time) | Persistent app data |
| Anonymous volume | Docker's storage area, random name | No | Yes | Throwaway data |
| tmpfs | Memory | No | No | Temporary or sensitive data |

### Useful options

| Want to… | Short form | Long form |
|----------|------------|-----------|
| Make it read-only | `/opt/sysops:/usr/local/apache2/htdocs:ro` | `read_only: true` |
| Fix SELinux access (shared) | append `:z` | `bind: { selinux: z }` |
| Fix SELinux access (private to this container) | append `:Z` | `bind: { selinux: Z }` |

> **Rule that caused the Attempt 3 failure:** each path inside the container can have **only one** mount. Choose one method per target.

---

## 7. Key takeaways

1. **Spaces, never tabs**, in YAML. If you see "cannot start any token", look for tabs with `cat -A`.
2. **Indentation is structure.** A setting that isn't indented under its service is read as something else entirely.
3. **Ports are `HOST:CONTAINER`.** The right side must be the port the app listens on.
4. **Service name ≠ container name.** Use `container_name:` when the exact container name matters.
5. **One mount per container path.** Pick bind *or* volume, not both.
6. **Bind mounts don't need a top-level `volumes:` block**; named volumes do.
7. **Validate early and often** with `docker compose config`, because errors surface one at a time.
8. **Not every error is about the file.** `unknown shorthand flag` means the command itself was mistyped.

---

## Appendix: error quick-reference

| Error message | What it means | Fix |
|---------------|---------------|-----|
| `found character that cannot start any token` | Tab characters in the YAML | Replace tabs with spaces |
| `services.<name> must be a mapping` | A setting was indented as if it were a service | Indent it under the correct service |
| `volumes must be a mapping` | A named volume declared without a colon | Write `httpd-data:` |
| `duplicate mount point` | Two mounts target the same container path | Keep only one |
| `bind source path does not exist` | Long-form bind with a missing host folder | Create the folder, or use `create_host_path: true` |
| `unknown shorthand flag: '0' in -0` | Mistyped command option | Retype the command; check `docker compose version` |
| `container name "/httpd" is already in use` | An old container has the same name | `docker rm -f httpd`, then rerun |
| Container runs but gives no response | Wrong container port in the mapping | Container side must be 80 for Apache |
| `curl` returns 403 Forbidden | Empty host folder or SELinux | Add content; use `:z` on CentOS/RHEL |
